= Antora Documentation Site UI

The Trento documentation site uses the https://gitlab.com/antora/antora-ui-default[Antora default UI] with a small set of Trento customizations layered on top as https://docs.antora.org/antora/latest/playbook/ui-supplemental-files/[supplemental UI files].
There is no UI project to build and no UI bundle to commit: Antora downloads the latest stable default UI bundle on every build and applies the files from `trento-docs-site/supplemental-ui/` over it.

Both are configured in the `ui` key of `trento-docs-site/antora-playbook.yml`.

== Project Structure

[source]
----
trento-docs-site/supplemental-ui/
├── css/trento.css                  # Trento branding, loaded after the default site.css
├── font/                           # Lato and eos-icons (Roboto comes from the default UI)
├── img/                            # Trento logos and icons
├── js/trento.js                    # Mobile search toggle
├── layouts/default.hbs             # Default page title
└── partials/
    ├── footer-content.hbs          # No footer
    ├── footer-scripts.hbs          # Loads js/trento.js
    ├── head-icons.hbs              # Trento favicon
    ├── head-styles.hbs             # Loads css/trento.css
    └── header-content.hbs          # Trento header, navigation links and search
----

A supplemental file replaces the file with the same path in the default UI bundle.
New files, such as `css/trento.css`, are added to it.

== Customize the UI

* To change a template, copy the partial or layout from the https://gitlab.com/antora/antora-ui-default/-/tree/master/src[default UI sources] into `supplemental-ui/` and edit the copy.
  Only override what you need, so improvements to the default UI keep flowing in.
* To change styles, edit `css/trento.css`.
  The default `site.css` is published with all CSS custom properties already resolved, so redefining a variable has no effect.
  Restate the affected rule with the same selector instead; it wins because `trento.css` is loaded last.
* Don't restate default rules just to undo upstream changes: the site follows the default UI, and `trento.css` only holds what Trento changes.

== Preview Changes

Supplemental files are applied by Antora itself, so the regular docs hub build shows UI changes directly.
Use `docker compose up` or run `npx antora antora-playbook.yml` from `trento-docs-site/`, as described in the xref:trento-docs-site/README.adoc[docs hub README].

To learn how to customize templates, partials, helpers, and other UI components, refer to the official Antora UI customization guide:

https://docs.antora.org/antora-ui-default/templates/
